Vision

temoa OS ist das interne Amazon-Betriebssystem der Agentur. Alle verstreuten Datenquellen — Seller Central, Ads-Konsole, Helium 10, Reviews, Listings — fließen in ein Tool, das sie in priorisierte Maßnahmen und fertigen Content übersetzt, vom Account bis zur ASIN. Jede Zahl trägt Formel und Quelle. Jeder generierte Text besteht ein deterministisches Prüf-Gate. Keine Fassaden-Daten. Zuerst intern; Kunden-Accounts sind Zielbild, nicht v1.

Sprint-Plan — 1 Woche, 1 Outcome, 1 prüfbare Abnahme

Reihenfolge S3–S6 ist Vorschlag; wird je Sprint-Wechsel gemeinsam bestätigt.

S1

Optimizer verlässlich braucht E1

Ein echtes Kundenprodukt wird komplett durchoptimiert, ohne dass irgendwo etwas hakt: Review-Actor tauschen, End-zu-End-Härtung der Werkbank.

Abnahme: 3 echte ASINs von Import bis freigegebenem Content ohne Fehlercode; Review-Ausbeute plausibel gegen die Amazon-Seite.

S2

Monats-Rhythmus Reporting

Der Monatsbericht eines Kunden entsteht komplett im Tool: Retouren-Bericht + Retourenquote, SQP-Szenario-Rechner, geführter Monats-Upload.

Abnahme: Ein kompletter Kundenmonat hochgeladen → Cockpit, Diagnose und Hebel-Liste stimmen mit der Handrechnung überein.

S3

Content Phase 2: Bilder & A+ braucht E2

Bild-Briefs werden zu fertigen Bild-Prompts; A+ wird generiert und geprüft wie Bullets — sobald eure Quellen (Hauptbild-Prompt, A+-Regeln) da sind.

Abnahme: Für 1 Produkt entstehen Hauptbild-Prompt + A+-Entwürfe aus echten Daten, regelkonform geprüft.

S4

Intelligenz-Schicht v1

Das Tool nennt pro Marke die 3 wichtigsten Maßnahmen mit €-Hebel und Begründung; erste Alerts auf Ausreißer.

Abnahme: Advisor nennt 3 Maßnahmen mit Quelle, Formel, €-Korridor; Alert feuert auf präparierten Ausreißer.

S5

PPC-Ausbau

Search-Term-Findings werden zu umsetzbaren Kampagnen-Änderungen: Negativ-/Gebots-Checkliste mit Export, Struktur-Vorschlag aus dem Keyword-Tiering.

Abnahme: Aus einem echten Search-Term-Report entsteht eine exportierbare Negativliste + Struktur-Vorschlag.

S6

Skalierung

Marketplace-Switcher auf Markenebene, kategoriedynamische Fakten-Felder, SP-API-Spike (Gebühren-Schätzung als erster Adapter).

Abnahme: Produkt auf amazon.fr angelegt + importiert; API-Gebührenschätzung gegen PDF-Tabellen geprüft.

Arbeitsregeln — gelten in jedem Sprint

  • Keine Annahmen ohne HerleitungParser & Regeln nur mit echter Beispieldatei oder Quellen-Dokument. Blockiert heißt blockiert.
  • LLM generiert, Code erzwingtJede LLM-Antwort läuft durch Normalisierung + deterministisches Gate.
  • Ehrliche DatenKeine Fassaden-Scores; Stichprobe ≠ Gesamtzahl wird ausgewiesen.
  • Fehler als Popup mit CodeNie eine nackte Fehlerseite; Buttons nur klickbar, wenn sie Neues erzeugen.
  • Anti-BlackboxNeue Formel ⇒ Eintrag in Daten & Formeln im selben Commit.
  • Ein Feature = ein CommitMit Tests; DECISIONS.md wird fortgeschrieben.
